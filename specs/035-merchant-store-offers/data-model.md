# Data Model: Merchant Stores, Categorised Offers and Redemption Reports

Migrations `045`–`047`, idempotent in the style of the existing files. Column names follow the existing snake_case. Columns below are the design, not final SQL.

## 045 — `benefit_kind` values

`ALTER TYPE benefit_kind ADD VALUE IF NOT EXISTS 'freebie'` and `'bogo'`. In its own file because a new enum value cannot be used in the transaction that adds it.

## 046 — `stores`, `offer_categories`, `offer_media`, offer columns

### stores

| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| organisation_id | uuid NOT NULL | `UNIQUE`: one store per organisation. Composite FK `(organisation_id, kind)` → `organisations (id, kind)` with `kind = 'merchant'` |
| description | text | ≤ 2000 chars |
| cover_asset_id | uuid → assets | `ON DELETE RESTRICT`. An image, within 2% of 16:9, checked by the application when it is set (dimensions come from the asset row, probed at upload) |
| opening_hours | text | ≤ 500 chars |
| active | boolean NOT NULL DEFAULT true | Staff-only |
| deactivated_at | timestamptz | NULL while active |
| deactivated_by | uuid → admin_users | |
| deactivation_reason | text | Required when `active = false` |
| created_at / updated_at | timestamptz | `updated_at` is the version for edit conflicts |

Checks: `active OR (deactivated_at IS NOT NULL AND deactivation_reason IS NOT NULL)`. Name and logo come from `organisation_profiles` (no duplication). Locations stay in `merchant_locations`. A trigger refuses DELETE (a store is deactivated, never deleted).

### store_media

| Column | Type | Notes |
|---|---|---|
| store_id | uuid → stores `ON DELETE CASCADE` | |
| asset_id | uuid → assets `ON DELETE RESTRICT` | Removing the link never removes the bytes |
| position | smallint | `CHECK (position BETWEEN 0 AND 9)`; at most 10 per store |

`PRIMARY KEY (store_id, position)`; index on `asset_id`. The cover is not part of this table.

### offer_categories

| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| slug | citext UNIQUE | Stable code for the clients |
| name_de, name_en | text NOT NULL | 1..80 chars |
| position | integer NOT NULL | Display order |
| visible | boolean NOT NULL DEFAULT true | A hidden category stays on its existing offers |

Starter rows inserted by the migration (restaurants, health, beauty, shopping, travel, services, education, other). A trigger refuses DELETE while any offer references the category; no delete route exists in this feature.

### offers (altered)

| Change | Notes |
|---|---|
| `store_id uuid NOT NULL → stores (id)` | Backfilled: a store is created for each organisation that already has offers. A trigger checks the store belongs to the offer's organisation |
| `category_id uuid NOT NULL → offer_categories (id) ON DELETE RESTRICT` | Backfilled to `other` |
| `per_person_limit integer` | NULL = unlimited; default 1; `> 0` |
| `sort_position integer NOT NULL DEFAULT 0` | The merchant's display order within the store |
| existing `remaining` | NULL = unlimited, decremented under the offer row lock |

`offers_published_has_date` and `offers_real_advantage` stay. A new check: `benefit_kind NOT IN ('freebie','bogo') OR benefit_value IS NULL OR benefit_value > 0`.

### offer_media

| Column | Type | Notes |
|---|---|---|
| offer_id | uuid → offers `ON DELETE CASCADE` | |
| asset_id | uuid → assets `ON DELETE RESTRICT` | Removing the link never removes the bytes |
| position | smallint | `CHECK (position BETWEEN 0 AND 9)`; position 0 is the lead item |

`PRIMARY KEY (offer_id, position)`; index on `asset_id`. At most 10 items per offer is therefore a database fact.

## 047 — `redemptions` for any account

| Change | Notes |
|---|---|
| `member_id` replaced by `redeemer_kind account_kind NOT NULL` + `redeemer_id uuid NOT NULL` | Backfilled `member`. FK dropped (see Complexity Tracking); an insert trigger checks the id exists for its kind and the account is active |
| `request_id uuid NOT NULL` | `UNIQUE (redeemer_kind, redeemer_id, request_id)`: a retry returns the original |
| `organisation_id uuid NOT NULL` (denormalised from the offer) | Merchant report scope; set by the insert, never edited |
| `category_id uuid NOT NULL` (denormalised from the offer at redemption time) | A later category change does not rewrite history |
| `estimated_saving_cents` | Unchanged; NULL for freebie and bogo |
| existing `reference` | `UNIQUE`; deterministic, generated by the server |

Append-only: a trigger refuses UPDATE and DELETE (the `referrals` ledger pattern). Tests clear the table only through a TRUNCATE helper. Indexes: `(organisation_id, redeemed_at DESC, id)` for the merchant report; `(category_id, redeemed_at DESC)`; `(redeemer_kind, redeemer_id, redeemed_at DESC)` for "mine"; `(offer_id, redeemer_kind, redeemer_id)` for the per-person limit.

`redemption_feedback` is untouched; it still joins on `redemption_id`.

## Visibility predicate (shared)

```
VISIBLE_OFFER :=
    offers.state = 'published'
AND now() BETWEEN offers.valid_from AND offers.valid_until
AND (offers.remaining IS NULL OR offers.remaining > 0)   -- list/detail show "sold out"; redeem refuses
AND stores.active
AND organisations.status = 'active'
```

## State transitions

- **Store**: `active → inactive` (staff, reason required, audited) and back. Creating the store makes it active.
- **Offer**: `draft → published → withdrawn`. Publishing needs a store that is active, a category, a valid window and at least the required fields. `pending` and `rejected` are unused here.
- **Category**: `visible ↔ hidden`; never deleted.
- **Redemption**: created once, never changed.

## Relationships

```
organisations 1─1 stores 1─* offers *─1 offer_categories
                              offers 1─* offer_media *─1 assets
                              offers 1─* redemptions *─(kind,id) accounts
organisations 1─1 organisation_profiles (name, logo; read by the carousel and the store page)
```
