## Implementation strategy

**MVP = Phases 1–3 (US1)**: the dashboard figures, a read-only server route and one client screen, with no permission-model change. **US2** makes Roles & permissions real and read-only, which already removes "Not available yet". **US3** is the risky part (it can lock the club out of administration), so it comes last and is built test-first against the three existing rules (last superadmin, self, administrators), with the database trigger as the backstop for races.

Open question carried from the spec: "requests" is shown as two figures (waiting applications and listing requests in 30 days). If you meant only one, drop the other from `DASHBOARD_FIGURES` in T003 and the labels in T011 before starting.
