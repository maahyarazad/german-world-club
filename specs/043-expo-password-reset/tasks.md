# Tasks: Reset a forgotten password in the app, by SMS code

**Input**: Design documents from `/specs/043-expo-password-reset/`

**Prerequisites**: plan.md, spec.md, research.md (R1 to R16), data-model.md, contracts/ (`password-reset-code-api.md`, `expo-reset-ui.md`, `public-screens-style.md`), quickstart.md

**Tests**: **Included.** The spec does not ask for TDD, but the constitution requires every principle a change touches to have an automated check that fails the build, CLAUDE.md requires each test to carry a counter-assertion (one that would fail against a server that did nothing), and plan.md and quickstart section 9 list the suites. Write each test first and watch it fail. The Expo app has **no test runner** (only `lint` and `typecheck`), so Expo tasks end in those two commands and a device check. The look-and-feel stories (US4, US5) add two small vitest guards in the web client's test folder (`client/tests/assets/`, where `fallback-parity.test.ts` already reads the app's files), because that is the only runner that can read the app's source.

**Organization**: grouped by user story (spec US1 to US5). **US1 and US2 are both P1 and ship together**: a code that arrives but cannot be redeemed, or a redeem screen with no way to get a code, is not a feature. **US4 and US5 (both P2) are the requested look**: US4 (the backdrop) needs nothing from the other stories and can ship alone, even first; US5 (sign-in, forgot-password and reset-password share one look) needs the two new screens. The shared `AuthScreen` (T014) is built in Foundational so the new screens are built on it once, not built and then restyled.

## Conventions every task follows (from CLAUDE.md)

- **Server tests run against a scratch database, never dev or production**: they `TRUNCATE` tables. Take the URL in `server/.env`, change only the database name to a scratch one (e.g. `gwc_test`), and pass it as `DATABASE_URL` on the command line. Run one file: `cd server && DATABASE_URL=<scratch url> npx vitest run tests/auth/password-reset-code.test.ts`.
- Queries in `server/src/**/application/` **name their columns**; never `SELECT *`.
- A route declares `config.auth`; an undeclared posture refuses to boot. A public route is an affirmative `audience: 'public'`.
- **Every SMS goes through `app.sendOtp`** (`tests/auth/sms-gateway.test.ts` scans `src/` for any other caller). Never call the provider directly.
- **A one-time code carries a purpose and endpoints redeem only their own.** Never reuse another purpose to avoid the migration (research R1).
- The server emits no localised text; problems are branched on `type`, never `detail`.
- **Nothing sensitive in logs**: `email`, `mobile`, `code` and `password` in a request body are already redacted by `REDACT_PATHS`; never log them yourself, never put one in a URL or an audit `detail`.
- Interface strings live in the i18n catalogues, German and English both. The app's German uses the formal "Sie".
- **Expo**: no inline style objects (`StyleSheet.create`; theme colours through `useThemedStyles`); a catch logs `console.error('<Component>.<function>', error instanceof ApiError ? error.problem : error)`; read the Expo 57 docs first (T003).
- Server `tsc` has ~1,800 errors on `main`; the bar is **no new ones** (compare against `main`, not zero).
- **The requester's uncommitted work is part of this feature** (research R16): `src/constants/theme.ts` (`BackdropScrim.light = ''`) and the untracked `assets/main-bg-dark-01.png` and `assets/main-bg-light-01.png`. Build on it. Never `git stash`, `git checkout --` or `git clean` the working tree. It is committed with the tasks that finish it (T037, T038).
- **Backdrop images**: never `require` a 4875 x 10550 original (`*-01.png`, `main_bg.png`): decoding one costs hundreds of megabytes. The app ships the 1170 px copies (research R12). A wash is always a valid colour: `'transparent'` for none, never `''`.
- **Public auth screens** (`sign-in`, `forgot-password`, `reset-password`) are built on `AuthScreen` and their actions are only the standard `Button` / `AsyncButton` (primary for the main action, `variant="secondary"` for the rest): no `Pressable`, no text link (research R15). Do not change `Button` or `FormScreen` for this; other screens use them.

## Notes

- Never mark a task done on "it compiles". Server tasks end on their named test going green; app tasks on `typecheck`, `lint` and the device check.
- **Do not reuse another one-time-code purpose to avoid the migration.** If the requester refuses any migration, stop and re-plan with research R1's fallback; do not improvise.
- **Do not make the ask answer depend on the identifier**, in status, body, headers or whether a send was attempted before the reply. If a new failure mode appears (a new SMS error), it is logged, not surfaced.
- **The password is validated before the code is checked, and the code before the password is hashed.** Do not reorder either.
- The staff, merchant and partner reset stays the emailed link on the web; do not add an email fallback here.
- **Do not `require` a 4875 x 10550 original, and do not lower the dark wash below 0.45 to "show more art"**: the first costs hundreds of megabytes on a phone, the second makes secondary text unreadable (research R12 and R13). T036 fails the build for either.
- **Do not get "the same buttons" by editing `Button` or `FormScreen`.** Other screens use them. The look is `AuthScreen` plus standard buttons placed in it (research R15). If the requester meant a different button design from the welcome screen's, that is a separate change to `Button` and affects every screen.
- Commit after each task or logical group; end commit messages with the attribution line the harness supplies.
